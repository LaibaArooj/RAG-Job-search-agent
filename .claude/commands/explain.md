Explain: $ARGUMENTS

I have to defend this project in a viva. Explain it the way an examiner would want to hear it
from me, not the way documentation would put it.

Cover:
1. **What it does** — in two sentences, no jargon.
2. **Why it exists** — which SRS requirement or SDD design decision it satisfies. Cite the FR
   or TC number.
3. **How it works** — walk the actual code line by line where it's non-obvious.
4. **Why this approach** — what the alternatives were and why this one was chosen.
5. **What an examiner might attack** — the weakest point in the design, and the honest answer
   to give if asked about it.

Then ask me two questions to check I actually understood it. Don't accept a vague answer.
